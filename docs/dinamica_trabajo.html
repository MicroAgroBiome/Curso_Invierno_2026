Antes del curso

Elige dónde vas a ejecutar el código

  • Google Colab (recomendado)
  • En tu computadora

No necesitas instalar nada; solo una cuenta de Google.

  1. Abre el notebook con el botón Open in Colab del capítulo correspondiente.
  2. Guarda una copia en tu Drive (Archivo → Guardar una copia en Drive): así conservas lo que escribas.
  3. Ejecuta la celda de Setup: instala las librerías que faltan y descarga los datos automáticamente (no necesitas descargar nada a mano).
  4. Si ves Entorno: Google Colab, todo está listo.

Para quien ya trabaja con Python localmente (VSCode o Jupyter).

git clone https://github.com/MicroAgroBiome/MicroAgroBiome_bioinfo2026_libro.git
cd MicroAgroBiome_bioinfo2026_libro

source venv/bin/activate        # en Windows: venv\Scripts\activate

Abre el notebook y ejecuta la celda de Setup; debe decir Entorno: Local (VSCode).

Dinámica de cada sesión

En las lecciones con notebook trabajamos con codificación en vivo participativa, al estilo de The Carpentries: el instructor escribe el código en pantalla, explicando cada línea, y tú lo escribes al mismo tiempo en tu notebook. Escribirlo (en vez de solo ejecutarlo) es lo que te ayuda a entenderlo y recordarlo.

Cada concepto sigue el mismo ciclo:

  1. Explicación (instructor): se presenta el concepto con el capítulo del libro en pantalla.
  2. Predicción (todos): antes de ejecutar, respondes en el Etherpad qué esperas ver (bloques 🔮).
  3. Código en vivo (todos): escribimos juntos las celdas marcadas con ⌨️. Las demás, sobre todo las de gráficas, ya vienen escritas: solo se ejecutan.
  4. Ejercicio (individual): completas el código o respondes una pregunta, con un tiempo indicado.
  5. Solución y discusión (grupo): se revisa la solución y, sobre todo, la interpretación del resultado.

Al final de cada sesión, la última media hora a una hora es tiempo de proyecto: los equipos aplican a sus datos lo que se vio ese día (ver Proyecto del curso).

Si te atrasas o algo falla

  • Pide ayuda sin detener la clase: levanta la mano (en el salón) o escribe en el chat o en el Etherpad (en línea); uno de los instructores o helpers te atiende.
  • Copia del Etherpad: después de escribir cada bloque, el instructor lo pega en el Etherpad.
  • 🛟 Ponerse al día: al inicio de cada sección hay una celda de rescate (con el código oculto) que recrea todas las variables anteriores. Ejecútala solo si te atrasaste o algo falló.

Cómo son los ejercicios

Los ejercicios no piden escribir código desde cero. Hay cuatro tipos:

  • Predecir (🔮): antes de ejecutar, anotas qué esperas que salga.
  • Completar una línea: reemplazas TU_CODIGO_AQUI por una función, un valor o un nombre de columna.
  • Cambiar y comparar: cambias un parámetro (una métrica, un número de grupos) y comparas con el resultado anterior.
  • Interpretar: respondes preguntas sobre una figura o un resultado, sin escribir código.
# Ejemplo (Lección 1, Ejercicio 2)
fabaceae_samples = merged_table[merged_table["host_name_family"] == TU_CODIGO_AQUI]

Si ejecutas un ejercicio sin completarlo, verás:

NameError: name 'TU_CODIGO_AQUI' is not defined

Es intencional: indica qué línea falta completar.

Las soluciones están en el capítulo del libro, en bloques plegados “Solución” debajo de cada ejercicio. Intenta resolverlo primero; la solución incluye una explicación del resultado.

Síntoma Qué hacer
NameError: TU_CODIGO_AQUI Es un ejercicio sin completar: reemplaza TU_CODIGO_AQUI.
NameError con otro nombre Falta ejecutar (o escribir) una celda anterior. Ejecuta la celda 🛟 Ponerse al día más cercana hacia arriba.

Perdí lo que había escrito Abre tu copia desde Drive (Archivo → Abrir notebook). Si no guardaste copia, vuelve a abrir el notebook y usa las celdas 🛟.
Mi figura no se parece a la del libro Revisa que no cambiaste parámetros fuera del ejercicio; si persiste, pregunta.

Para instructores: cómo se produce el material

Todo sale de una sola fuente: el notebook completo ejecutado (notebooks/leccion_N_*.ipynb).

  • El libro toma de él el código y las figuras ({{< embed ... echo=true >}}) y no vuelve a ejecutar nada, por lo que quien renderiza no necesita Python ni los datos.
  • El notebook del participante (notebooks/participante/) se genera con un script: nunca se edita a mano.
  • El notebook del proyecto (notebooks/proyecto_maiz.ipynb) y las páginas interactivas (interactivos/) se suben tal cual: no pasan por el generador.

Reglas:

  1. Ejecutar el notebook completo antes de cada commit: las figuras del libro son exactamente esas salidas. Las celdas de ejercicio fallan a propósito, por eso se usa --allow-errors. Se necesitan nbconvert, nbformat e ipykernel en el entorno:

    jupyter nbconvert --to notebook --execute --inplace --allow-errors notebooks/leccion_1_introduccion_datos.ipynb
python scripts/generar_notebook_participante.py notebooks/leccion_1_introduccion_datos.ipynb

  2. Etiquetas de celda del notebook completo (en VSCode: ... de la celda → Add Cell Tag), que usa el script generador:

    Etiqueta En el notebook del participante
    teclear Queda vacía; solo conserva su comentario guía # ⌨️ ... (obligatorio)
    estado Su código se copia a las celdas de rescate posteriores
    rescate Se llena con el código de las celdas estado anteriores (🛟, con el código oculto)
    solucion, instructor Se eliminan

  3. No hacer commit de docs/ en las ramas: es salida generada y provoca conflictos en los merges.

  4. Las celdas cuyo código o salida aparece en el libro llevan al inicio una etiqueta de Quarto, por ejemplo:

    #| label: fig-l1-profundidad
#| fig-cap: "Distribución de la profundidad de secuenciación."

    Las etiquetas viven en el propio notebook: si una celda nueva debe aparecer en el libro, agrégale su #| label: a mano. Las de gráficas llevan además #| code-fold: true para que el libro muestre su código plegado.

  5. La URL del repositorio aparece en un solo archivo (_variables.yml), para que un cambio de nombre del repo sea una edición de una línea.

  6. Datos: el subconjunto de clase (datos/subset.zip) y el del proyecto (datos/subset_proyecto.zip) se generan con scripts/02_make_subset.py; su receta y su registro (taller_samples.csv, subset_log.txt) van dentro de cada zip. Nunca sobrescribir datos/subset/ al generar otro subconjunto: usar siempre --out-dir propio.
